Exceptions:

On exception, "call 0" with all exceptions masked off.
Reset is special in that sp and csp are also zeroed.

Design notes:

Faults include stack over/underflows, illegal instructions, and (possibly) illegal memory access. There is no built-in mechanism to identify faults. The reasoning here is that the actual fault isn't terribly interesting: where in the code the fault happened and the backtrace from that point are much more useful for debugging. So, keep the processor simple here, and use the return stack contents as primary clues when debugging.

If faults are masked, stacks "wrap-around", illegal instructions and bad memory writes are nops, while bad memory reads yield 0.
